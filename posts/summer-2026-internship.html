My summer 2026 internship at Leidos Dynetics in Huntsville, Alabama. Following up on last year's work and taking on new challenges.

Week 3 (06/01/26)

Presenting the Architecture

This week, Skye and I were pleased to present to Mundy a new, more general orchestration/supervisor style architecture. Upon first proposal, he actually seemed to like it! In our meeting, we presented our idea but left off our idea for a "validator" agent and we were going to bring it up at the end, but Mundy suggested it before we could get to that part. So that was pretty cool to be able to be like "yeah we already thought about that."

The naive, more simple, way of doing this is without a validator and just letting the orchestrator deal with that. But that goes against the whole specific agentic paradaigm. A more thoughtout, more agentic, solution would look something like this:

  • Orchestrator: takes in user input and creates a plan / tasks and directs different agents to do things. Retreieves relevant context from the context manager
  • Context Manager: holds onto context from throughout the conversation(s) as well as throughout the user interactions
  • Validator: Checks after LLM generations if the agent did what was expected. If not, requery.

Developing side by side with someone else is a very interesting task. Especially because I tend to work faster than most (including Skye) and I have a very different development style than most. I tend to jump in quickly and want to prototype while most people want to research deeply before jumping in. There's pros and cons to both, I just find reading boring and less usefull than writing for me. However, I am forced to slow down and explain my ideas to Skye before jumping in, otherwise I'm a dick of a partner for a project. This has been actually quite helpful. Sometimes I'll turn around to explain the architecture I'm about to implement and while talking about it I'll remember something or find something I don't like and can talk through it.

One cool thing I thought of that I really like in our architecture has to do with the librarian. The librarian is an agent that can write custom SQL queries (and a few premade ones) to query a database. This agent is a READ-ONLY agent. Many people would jump to having an agent that can do READ and WRITE but we're trying to lean into specialization as much as we can as to reduce the cognative load on the models.

Side Project: Command Line Devlog

I write these blogs at the end of the week or at the start of the next week. But during the week I keep a devlog. The devlog is kind of just a stream of conciousness in a markdown file where I record the date and time then just write whatever I'm doing or thinking. It can be annoying to keep a whole visual studio editor open, and I dont like notepad much. So for a while I was using powershell's "edit" command line editor to have it always open. But that got a little annoying because I like to keep my windows organized and alt-tabbing through unused things is annoying. So one morning I took an hour or so to do a little side project. Now, I know its not much of a "brag", but I used absolutely no AI to do this project. I used a specifc browser with no AI in the search results and what not. This was a nice break from the super fast paced AI world that we live in now.

The project was to learn to write a batch file (I havn't even thought about Batch scripting in 6 years) to allow me to log thoughts as they come to me without having the file always open. So I researched and learned how to write batch scripts! Some cool features are it automatically record the time, allows for mutli line input until you type "q" and press enter, and it automatically puts the date. The date thing was a fun one because I had to write it to where it will read the whole file and look for the date, and if not then add it. I also made it accessable anywhere so I can just type "log" in my CMD or PShell and it will call that script and allow me to type into the one dev log. I was pretty proud of the script and had a really fun time making it. Here's the code:

@ECHO OFF
setlocal enabledelayedexpansion

set d=%date%
set hhmm=%TIME:~0,5%
set logfile="C:\Users\hancep\Documents\notes\devlog.md"

findstr /c:"%d%" %logfile% > nul
IF %ERRORLEVEL% EQU 0 ( echo. ) ELSE ( echo ### %d% >> %logfile% )

echo.>> %logfile%
echo #### %hhmm%>> %logfile%

echo Write Your Log Here (type q to quit):
:log_start
set /p input=": "
if /i "%input%"=="q" exit /b
echo(!input!>> %logfile%
goto log_start
